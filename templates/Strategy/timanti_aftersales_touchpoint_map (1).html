Change / Piece & Size Swap  —  0 dedicated emails  ·  no automation exists for this path
"Change" (customer swaps for a different piece or a different size rather than returning for money) has no tag, no route and no template anywhere in the middleware. It is executed today by borrowing other mechanisms: a fresh draft order for the replacement piece, plus an exchange note or voucher to carry the old value across. Note the policy tension — resized or altered items are explicitly not returnable, so a size change is a one-way door once done.

Staff & HQ Action Reference
TAG repair-intake — the single entry point to the entire repair journey. Nothing fires without it. Add it to the repair draft order once the piece is physically in hand and the item description is filled.
TAG free-repair — alternative to HQ ticking "our mistake" on the estimate form. Both routes converge on the same dedup guard, so tagging after HQ has already marked it free will not double-send.
HQ Set Estimate — signed link inside the intake email. Setting the amount prices the draft line item and releases the customer estimate + GoKwik link in one step. The customer is waiting on this; nothing chases it.
HQ Mark Repair Complete — signed link inside every HQ email. Enter the Sequel AWB for dispatch, or tick store pickup. Submitting with neither still emails the customer, but with a "we'll be in touch" promise nothing schedules.
SEND Tax invoice after any adjustment — exchange note, voucher and old gold all land as post-tax rows on the invoice. The adjustment email confirms the accounting entry only; the customer sees the arithmetic solely on the invoice, which staff must send.
WA Everything on the returns and online-exchange paths — request acknowledgement, pickup coordination, QC outcome, value quote and rejection are all manual WhatsApp or phone. No templates exist and nothing is logged against the order.
⚑ Before go-live — clear REPAIR_TEST_EMAIL in services/repairs/index.js, set SEND_CUSTOMER_EMAILS = true in apps-script.js, and confirm HQ_EMAIL (plus optional HQ_CC_EMAIL) are set on the middleware — a missing HQ_EMAIL silently skips every internal email and tags the draft repair-hq-email-failed.
